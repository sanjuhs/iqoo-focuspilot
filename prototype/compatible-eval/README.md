# Compatible System 1 and Qwen unit pipeline

This separate pre-event research study keeps Qwen3.5-0.8B Q4_0 selected. A local
complete-request parser handles familiar bounded commands; the same model can
propose copied quantity/unit slots for unfamiliar wording. Each accepted proposal
still requires the existing separate action review.

The checked-model and combined pipeline results are distinct. A local parser hit
is not a Qwen prediction, and a heatmap cannot explain the parser's decision.
Both model arms capture every request for controlled research. Actual inference
times do not measure the future pipeline's fast-path benefit.

The candidate, known-data checks, prospective protocol and opaque exclusion
inventory are committed before the informed author creates fresh requests.
All100 manually labelled rows are reviewed before output. Each native arm has
one attempt with pinned existing model/runtime and actual tokenizer preflight.
Failures and losses remain visible; no output-driven source or label repair.

Raw requests, labels, prompts and captures stay in ignored build directories.
Public records contain generic tools and hashes/counts. Passing the fixed
criteria permits exact app integration checks, not a full phone, NPU, Office Kit,
training, causal interpretation or eligible submission claim.
