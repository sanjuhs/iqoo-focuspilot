# Synthetic positive-weight policy laboratory

**Pre-event research, created 2 October 2026. Not an eligible event-created submission.** This is a standard-library Python experiment with an actually trained 65-parameter network. It does not integrate with the Android prototype, control a phone, debit money, interpret Laya/an LLM, or learn real human productivity. The Android prototype's hand-authored policy is a separate baseline.

Run from the repository root:

```sh
python3 prototype/policy/cli.py train
python3 prototype/policy/cli.py evaluate --output prototype/policy/evaluation.json
python3 prototype/policy/cli.py inspect --features 0.7,0.6,0.4,0.8,0.2,0.5 --intervene selected_app_budget_overrun=0.1
python3 prototype/policy/cli.py inspect --features 1,1,1,1,1,1 --paused
python3 -m unittest discover -s prototype/policy -p 'test_*.py' -v
```

The default training seed is 20261002, with 140 epochs and 160 examples per scenario family. `--seed`, `--epochs`, `--per-family`, `--learning-rate`, and `--output` select a new experiment. A custom output path keeps the committed reference artifact intact. `train` writes the model and measured results; `evaluate` regenerates the procedural data and verifies its manifest before evaluating. The saved artifact includes feature order, seed, optimizer, selection rule, source hash, dataset hashes, weights, and weight checksum. Training is deterministic for the same implementation and Python arithmetic; wall-clock timings are not deterministic.

## Features, teacher, and partitioning

All six inputs are dimensionless synthetic values in [0,1], ordered as:

1. `selected_app_budget_overrun`
2. `continuous_session_overrun`
3. `reopen_count`
4. `active_focus_overlap`
5. `deferred_nudges`
6. `elapsed_time_overrun`

Names describe proposed future risk features, not values calibrated from real phone usage. The invented label is generated by this known monotone rule:

```text
3.1*x0 + 2.3*x1 + x2 + 0.8*x3 + 0.55*x4 + 0.9*x5
  + 2.5*max(0, x0+x1-0.95) - 4.1 >= 0
```

Train families are broad mixtures, reopening, budget-dominant, and session-dominant (640 rows). Dev families are near balanced boundaries and split overtime (320 rows). Held-out families are correlated overruns, sparse extremes, and moderate-everywhere risks (480 rows). Families use separate deterministic seeds; rows are not randomly redistributed between splits. Every split uses the same invented teacher: this is a distribution-shift synthetic experiment, not a new-task or independent real-world evaluation.

Only train rows update weights. The best epoch is selected by dev binary cross-entropy; the decision threshold maximizes dev accuracy over 0.10–0.90 in 0.01 steps, preferring the closest to 0.5 on ties. Holdout is evaluated once after selection. Reporting scripts can rerun that fixed evaluation; repeated holdout-driven tuning would invalidate the claim of untouched holdout.

## Training and what the inspector proves

The network is `6 → 8 ReLU → 1 sigmoid`: 48 input weights, 8 hidden biases, 8 output weights, and 1 output bias. Connection weights remain nonnegative through projected SGD (`max(0, updated_weight)`). Biases are signed so the model can have a low-risk baseline and useful activation thresholds. The scalar risk score is monotone in every risk feature by construction. The learning-rate schedule and selected epoch are recorded in the JSON artifact.

For each hidden unit, the inspector provides its preactivation, ReLU activation, output weight, and **exact additive pre-sigmoid logit contribution**. These contributions plus the output bias sum to the logit. Suppressing a hidden unit shows the corresponding counterfactual probability. Feature ablations set one input to zero and recompute the full network; these score changes do not generally add up. A named intervention accepts an arbitrary replacement in [0,1]. No hidden unit is claimed to have a validated concept label.

Pause, permission, inactive focus, cooldown, and stale observations are deterministic external gates. They block a recommendation before scoring and cannot be overridden by confidence. The lab only returns `offer_nudge`, `allow`, or `blocked`; it executes no action and models no financial ledger. The inspector may still inspect explicitly supplied synthetic vectors while a separate external policy blocks the recommendation.

## Metrics and limitations

See `synthetic-model-results.json` for the training-run metrics and `evaluation.json` for the frozen evaluation and local warm CPU microbenchmark. Metrics include accuracy, precision/recall, false-nudge rate, cross-entropy, Brier score, probability-bin ECE, per-family holdout results, and 1,800 sampled monotonicity comparisons. A training-majority baseline and simple overrun rule are reported. The known teacher has 100% accuracy by definition; learning its artificial labels is not better than knowing the rule and is not evidence that a neural model is necessary.

The microbenchmark measures Python CPU forward passes on this development laptop, including input validation. It excludes speech, phone APIs, model-loading, app lifecycle, and end-to-end work. It is not a Snapdragon/NPU benchmark. High accuracy means matching this invented label function on these small synthetic distributions. It does not validate user benefit, sensible penalties, real-world calibration, fairness, few-shot learning, or the language model's internal mechanisms. Real deployment requires consented labels, scenario-separated evaluation, stronger baselines, validated feature extraction, and Android lifecycle tests.
