# Compatible System 1 and Qwen command research

Qwen3.5-0.8B Q4_0 remains the chosen model. This separate pre-event candidate
repairs the previous unit-output validator's regressions and adds a deterministic
complete-request recognizer. The installed v0.16 app, prompt and native runtime
remain unchanged while fresh qualification is pending.

The recognizer returns a reviewed proposal only for an unambiguous complete
bounded request. Unfamiliar wording can use the Qwen unit-output contract. Duration
arguments copy their original quantity/unit and convert to canonical seconds in
code; source agreement is mandatory. Explain is constrained to the entire local
focus-status vocabulary. Finite third-person and possessive checks limit local
state scope. These heuristics can overreject and do not establish arbitrary
language safety. Every action still needs the existing separate review.

Results label `FAST_LOCAL_REQUEST`, `CHECKED_MODEL` and `UNKNOWN`. A fast local
decision provides no Qwen prediction or activation evidence. Checked-model and
combined pipeline scores are reported independently.

## Prospective fresh qualification

The [protocol](../prototype/compatible-eval/protocol.json), candidate dependencies,
generic author tooling and opaque prior-request inventory were committed before
fresh authoring at `68b74c5c38c2f5d9334b76989e073bd5da586bd8`. The inventory covers
236 sources, 5,655 normalized hashes, 582 family hashes and 163 template hashes;
it includes exact structured/unit prompt examples. The informed synthetic author
may read only opaque metadata and its own generic tooling.

The planned cohort has 50 supported/unsupported reciprocal pairs, complete
canonical/source-unit manual labels and fixed class, app, unit and boundary
quotas. Every label is reviewed before outputs. One original-prompt and one unit
prompt CPU capture include all100 requests, including fast-path hits, so model
accuracy and pipeline success stay separate. Token budgets, actual JSON/EOS,
source/model/runtime bytes and process ownership are checked.

All fixed criteria must pass: at least six pipeline gains with no complete or
per-class losses, at least four Start proposals, no wrong accepted proposals,
all50 unknowns refused in both candidate modes, and no oracle decline. Raw
model-only predictions, paired semantic losses and complete proposal losses
remain visible even if the combined pipeline qualifies. No retry, post-output
source repair, omission or relabelling is allowed.

Fresh execution and results are pending. Qualification alone permits exact app
integration checks; it proves no Android action, voice/lifecycle, phone latency,
iQOO/NPU, Office Kit, training, causal interpretation or eligible submission.
Raw corpus, gold and captures stay ignored. Total logical workspace bytes after
the source freeze were 14,443,262,909, within the strict15GB cap. No new weights,
dependencies or phone permission changes were made.
