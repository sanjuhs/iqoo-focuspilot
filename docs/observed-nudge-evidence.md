# Current-foreground gate for real nudges

Pre-event research, 2 October 2026. The cumulative selected-app budget remains useful across app switches, but it must not repeatedly nudge a user who has already left the selected app. `ObservedNudgeGate` adds a separate eligibility check before the existing hand-set decision policy. It changes no neural weights, feature mapping, budget score, cooldown or virtual-point amount.

`SelectedAppObservation.Summary.selectedForeground` represents the state at the end of the currently queried event stream. It is meaningful only when `summary.complete` is true and is false for every incomplete summary. Anonymous other-app resume, selected-app pause and screen-off end selected foreground. A later observed selected resume can restore it; future resumes cannot establish it. Existing duration and reentry aggregation is preserved.

`ObservedNudgeGate.eligible(snapshot, expectedScopeId, nowElapsed, consent, usagePermission, activeFocus)` requires all three external gates, a non-null snapshot from the exact active observation scope, nonnegative query age of at most 15 seconds, a complete chronological summary, wall/monotonic clock alignment within two seconds and current selected foreground. Missing leading boundaries, out-of-order events, device-boundary gaps, stale snapshots and future query times cannot authorize nudges.

This gate deliberately does not require `snapshot.complete()`: that method additionally requires optional explicit continuous-app/planned-focus limits and all neural inputs. A user can keep the ordinary budget rule working without enabling the neural shadow trace. No synthetic score or few-shot Nudge recommendation can grant baseline eligibility.

Repository integration order is: refresh the opt-in observation; compute this foreground gate; pass it to the existing hand-set budget policy along with the unchanged cumulative duration/budget/cooldown; optionally apply a separately opted-in valid real-preference **Allow veto**; then apply the existing ledger. Evaluate fresh eligibility each tick. Do not cache a positive foreground or preference result across a pause, permission change or scope edit. This ordering is integrated in FocusRepository. The foreground notification and companion mood also respect current foreground and Allow-veto eligibility.

Seven foreground-gate tests and three repository-policy composition tests pass in the integrated host suite. Cases cover leaving the selected app despite a cumulative budget overrun, selected pause, screen-off, confirmed return with unchanged duration/reentry results, missing leading boundaries, future events, stale/future query times, opt-out/permission/pause/scope gating, invalid ordering and device restart. They also demonstrate that baseline eligibility can pass while optional neural limits remain missing.

No phone install, Gradle build, user-granted Usage Access session or notification behavior has been verified by this slice. On-device testing should exceed the selected app's budget, then leave it and confirm that the next polling tick produces no further virtual debit/nudge; repeat with screen-off and permission revocation. Query freshness is not proof of zero OS event-reporting delay. The known [foreground-boundary and OEM limitations](live-policy-evidence.md) still apply.
